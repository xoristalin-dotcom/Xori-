# Хори Кёко — 3D ИИ-помощник

## Локальный запуск

```bash
npm install
npm run dev
```

### Безлимитный локальный режим

Внешние API имеют собственные квоты, снять их настройкой приложения нельзя. Чтобы Хори продолжала отвечать после ошибки `429` или исчерпания ключей, установи [Ollama](https://ollama.com), затем скачай локальную модель:

```bash
ollama pull llama3.2:3b
```

Сервер автоматически пробует Ollama первым, а затем настроенные облачные провайдеры. Для Ollama Cloud используй `OLLAMA_BASE_URL=https://ollama.com/v1`, `OLLAMA_API_KEY` и модель `gemma4:31b`. Для локальной Ollama укажи `OLLAMA_BASE_URL=http://127.0.0.1:11434`, убери `OLLAMA_API_KEY` и скачай модель локально.

Для принудительно полного офлайн-режима запусти сервер с `OFFLINE_MODE=true npm run dev`: будут использоваться только Ollama и встроенный fallback.

Если Ollama не запущен, приложение использует встроенный персонажный fallback, но это не полноценная языковая модель. Локальная модель всё равно ограничена ресурсами компьютера и скоростью его CPU/GPU.

## Деплой на Render.com

1. Зарегистрируйся на [render.com](https://render.com)
2. Создай новый **Web Service** → выбери GitHub репозиторий
3. Render использует `render.yaml` из репозитория
4. В настройках Environment добавь секреты `BOT_TOKEN` из BotFather и `OLLAMA_API_KEY`, затем нажми **Deploy latest commit**

Telegram подключается автоматически через long polling после запуска Render. Отдельный webhook и отдельный сервис не нужны.

Сервис обязан запускаться командой `npm start` и слушать порт, который Render передает в переменной `PORT`.

### Настройка UptimeRobot

Для проверки доступности создай HTTP(s)-монитор с URL:

```text
https://<имя-сервиса>.onrender.com/api/health
```

Ожидаемый ответ: JSON со статусом `ok`. Пинговать локальный `localhost` или URL из dev container бесполезно: UptimeRobot должен обращаться к публичному адресу Render.

После деплоя существующий монитор UptimeRobot продолжит проверять `/api/health`; менять его не нужно.

На бесплатном тарифе Render может засыпать после периода бездействия. Внешний мониторинг иногда уменьшает такие простои, но не является гарантией работы 24/7; для постоянной работы нужен платный план.

### Постоянная Ollama в облаке

Render запускает приложение, но не является хорошим хостингом для самой Ollama: модель занимает место, требует постоянной памяти и часто GPU. Для облачной Ollama нужен отдельный постоянно работающий сервер или GPU-инстанс. На нём запусти Ollama, скачай модель и укажи в Render переменные `OLLAMA_BASE_URL` и `OLLAMA_MODEL`. Адрес должен быть защищён VPN или авторизацией, а не открыт для всего интернета.

Ключи Ollama Cloud, Kie.ai и другие API-ключи добавляй только в Secrets Render или локальный `.env`. Файл `ключ` уже исключён из Git. Так как ключи были опубликованы в чате, их следует отозвать и выпустить заново перед деплоем.

### Почему локальные программы не помогали

Скрипт, запущенный на компьютере, не удерживает процесс Render и не заменяет внешний HTTP-монитор. Кроме того, до исправления порта запросы Render попадали на порт `PORT`, а приложение слушало только `3000`, поэтому health-check не проходил.

Для ручной проверки:

```bash
curl https://<имя-сервиса>.onrender.com/api/health
```

### Чтобы сервис не засыпал на бесплатном тарифе:
1. Зарегистрируйся на [UptimeRobot](https://uptimerobot.com)
2. Добавь монитор: HTTP(s) → укажи URL `/api/health`
3. Проверь, что монитор получает HTTP `200`
